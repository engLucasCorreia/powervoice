## 2. How to try it

```bash
cd ~/Documents/dev/audition
just check                     # everything green: fmt, clippy, Rust tests, svelte-check, vitest

# measurement tool (used by every future acceptance test)
cargo run -q -p voxedit-cli -- gen sine --freq 1000 --level -20 --duration 20 -o - \
  | cargo run -q -p voxedit-cli -- analyze -
#   expect: peak -20.00 dBFS, rms -23.01 dB, integrated -23.00 LUFS
just fixtures                  # writes test signals + a 60-min file to fixtures/generated/
```

## 3. Decisions made during M0 (see `MEMORY.md` decisions log)
- Specs are written just-in-time per milestone; rack core, document model and CLI moved earlier (D-003, D-004).
- Document storage: disk-backed 64k-sample chunks, `Arc` snapshots, edit journal, crash recovery (ADR-004).
- Shared types: **ts-rs 12** (tauri-specta is still a pre-release) (ADR-003).
- **MP3 export:** LAME loaded at runtime via `libloading` (the `mp3lame-encoder` crate can only link statically, which conflicts with LGPL relinking) (ADR-007).
- **ysfx (JSFX)** library is Apache-2.0, not GPL; still sandbox-only for crash isolation (ADR-007).
- Installable modules = CLAP plugins built with `clack-plugin`, shipped as `.voxmod` packages (ADR-006).
- Plugin sandbox: one process per plugin instance (ADR-008).
- PROMPT §3.7 wording (`prepare`, `tail_samples()`) superseded by ADR-005 names (`activate`, `tail()`).
