# T-109 — M1 UI: device settings, transport bar, meter bridge, record panel, live recording strip

- **Milestone / wave:** M1 / W4
- **Tier:** Sonnet
- **Depends on:** T-106, T-107, T-108
- **Spec refs:** SPEC-001 §2.1–§2.3, SPEC-002 §2.1–§2.7 (UI parts, AC-12), SPEC-003 §2.1, §2.5 · **ADR refs:** ADR-003, ADR-009 · MEMORY D-014, D-018, D-020

## Goal
The owner can run the M1 checkpoint scenario entirely from the app window on real hardware.

## Scope
**In:**
- Settings → Audio Devices panel exactly as SPEC-001 §2.1 (host, input device, input channel, output device, rate, buffer, status dots, Rescan) with the §2.3 state table, notices and device banners.
- Transport bar: Play/Pause, Stop (returns to play start), Return to start, Play from start, Loop, Arm (Input), Record, running time; device-status control; keymap actions wired (T-104 registry).
- Meter bridge: input and output peak/RMS bars with ballistics (instant attack, 20 dB/s release, 1.5 s hold), −60…0 dBFS scale, clip latch (click to reset), readout of max peak.
- Record panel: New Recording dialog (rate/bit depth, defaults from settings), elapsed time, remaining disk time (amber < 10 min), dropout counter + "Go to first", clip count notice, monitoring selector + latency readout with amber/red warnings and one-time headphone hint.
- Live recording strip: a simple canvas (WebGL2 with Canvas2D fallback per ADR-009 §4) drawing `VXRP` min/max as it arrives and following the take end. The full waveform editor is M2.
- All strings via i18n; dark theme tokens.

**Out:** waveform editor, selection, spectral view (M2); rack panel UI (M4).

## Crates / files
`ui/src/lib/{settings,transport,meters,record,monitor}/`, `ui/src/App.svelte` layout slots.
