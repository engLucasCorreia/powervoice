# T-701 — Shortcut map audit (Audition-compatible)

- **Tier:** Sonnet (no review loop; blocking findings only)
- **Read first:**
  - CLAUDE.md, MEMORY.md (the H-26, T-709, T-206 and H-27/H-28 entries; decision A-020);
  - every spec that defines shortcuts (`grep -il shortcut specs/*.md`; SPEC-003 §3 is the main map);
  - the Shortcuts section of `docs/user-guide.md`;
  - the UI keyboard handling: the global key handler, the menus' `Kbd` chips, `ui/src/lib/ui/kbd.ts`, the tour key capture (`ui/src/lib/tour/*`), the waveform and spectral key handlers.

## Goal
One authoritative, conflict-free shortcut map that matches Adobe Audition's defaults wherever PowerVoice has the same feature. Every menu shows the right shortcut, and the docs list the same thing.

## Scope (in)
1. **Audit matrix.** For every command, record:
   - the spec binding, the implemented binding, the Audition binding (Windows/macOS), and the status (ok, missing, wrong, or conflicting);
   - platform mapping (Ctrl ↔ ⌘, Alt ↔ ⌥).

   Put the matrix in your report and in `docs/shortcuts.md`, generated from the registry (item 2).
2. **One registry:** `ui/src/lib/shortcuts/registry.ts` holds the command id, the default binding per platform, the i18n label and the scope (global, waveform, dialog or text input). It is used by:
   - the global handler;
   - the menus' `Kbd` chips, so menus can't disagree with the handler;
   - the Help → Keyboard Shortcuts list (if a view exists, or add a simple dialog built with the H-26 kit);
   - `docs/shortcuts.md`, generated by a script, with a check in `just check` that it's up to date.
3. **Fill the gaps:**
   - Missing bindings for existing commands, using Audition's where they exist.
   - A-020: keyboard nudge and extend of the selection, and of the cursor. Use Audition's bindings where they exist (for example, Shift+arrow extends); otherwise pick conservative, non-conflicting ones and document them.
   - Zero-crossing snap applies to keyboard-extended selection edges when the setting is on (T-206).
4. **Conflict rules, with tests:**
   - No two commands share a binding in the same scope.
   - Text inputs and the tour swallow keys correctly.
   - Space is play/stop, except in text inputs and while the tour is running.
   - Shortcuts respect dialogs, which are modal.

## Tests
- A registry test that fails on a duplicate binding in the same scope.
- A test that every menu item with a registry id shows the registry's chip.
- Handler tests for the new bindings, including nudge and extend.
- The docs check.

`just check` must pass.
